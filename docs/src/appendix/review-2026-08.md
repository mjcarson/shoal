# Review, August 2026

A full pass over Shoal's code and its documentation, done at once and on purpose: read the source
against every open claim, correct what had drifted, file what was not filed, and record what was
checked so the next review starts from a baseline instead of re-deriving one.

**No source file was changed by this review.** Everything below is either a correction to
documentation, a new entry on an existing index, or a measurement. The only non-`docs/` file it
touched is `CLAUDE.md`, which is itself documentation and was the subject of
[Resolved #25](resolved/claude-md-drift.md).

Tree: `ZeroCopyResponses` at `4f03e7e`. The `.rs` files that show as modified in the working tree
are the missing-archive fix ([Resolved #57](resolved/missing-archive.md)), which was already
uncommitted when this started and is not part of it.

## What had drifted

### Line numbers, nearly everywhere

Every `file:line` in [Known Issues](known-issues.md), [Optimizations](optimizations.md),
[TODOs](todos.md) and [Test Coverage](test-coverage.md) was re-resolved against the tree by script
and corrected by hand. **Most had moved**, some by more than a hundred lines — item 16's entire
panic table, every one of the eight in-code `TODO` rows, and the whole of O4's call-site table.

Two things are worth carrying forward from doing it:

- **A quoted historical entry keeps its historical line numbers**, and those now point at unrelated
  live code. O6's quote cites a `ring.rs` that is the tablet map now; O17's cites the pre-F5 shard
  loop. Both are annotated in place rather than renumbered, because renumbering a quote would make
  it a different quote.
- **The symbol name is the durable half of a citation.** Every corrected reference names the
  function or field beside the line, so the next drift is recoverable with `grep` rather than with
  another script.

## What was filed

Two defects and one optimization, all established by reading the source rather than by
reproduction — which is stated on each entry, per this documentation's own rule.

**[Item 59](known-issues.md#59-a-shard-that-cannot-free-anything-keeps-trying-on-every-message-in-silence)
— a shard that cannot free anything keeps trying, silently.** The eviction trigger is a level
re-tested every message, and `evict_data`'s "nothing left to evict" arm is a bare `break`. A shard
over its memory limit with nothing evictable therefore runs a futile pass per message forever and
logs nothing. [F9](../features/ephemeral-tables.md) makes this reachable: ephemeral partitions are
counted in `memory_usage` and never enter the LRU.

**[Item 60](known-issues.md#60-a-result-stream-that-is-not-drained-to-the-end-leaks-its-slot-in-the-client)
— an undrained result stream leaks its slot in the client.** The release of the `channel_map` entry
and the pooled channel pair lives inside `next`'s `if end` arm, and neither stream type implements
`Drop`. Dropping a stream early, or an `Err` out of `next`, leaks both — and every later response
for that query is then delivered into an unbounded channel with no reader. It is the client-side
twin of [item 32](known-issues.md#32-a-disconnected-client-is-never-cleaned-up-anywhere), and it
could not have been caught, because [the streaming APIs have no
test](test-coverage.md#the-streaming-client-apis).

**[O28](optimizations.md#o28-the-client-takes-two-guards-on-its-response-map-for-every-query-it-sends)
— the client takes two `papaya` guards per query where one would do.** Tiny, and filed anyway,
because it sits on the one layer of the system with no `tracing` spans and no `hotpath` scopes at
all: every macro number includes the client and none can attribute anything to it.

Two existing entries were widened rather than duplicated:
[O11](optimizations.md#o11-a-fresh-alignedvec-per-write-and-per-response) gained the client's
per-bundle allocation and the compactor's per-partition one;
[O14](optimizations.md#o14-fixed-thousand-element-preallocations-on-per-call-paths) gained
`evict_data`'s per-call `HashMap` and `SerializedMap::save`'s pair of thousand-element rebuilds.

## What was expanded

Three pages gained the material this review found they were missing. In each case the addition is
the *contract* rather than the walkthrough — what holds the code up, not what it does.

**[The Client](../api/client.md#the-reorder-buffers)** — the reorder buffers. They are the only
client state spanning responses, the part most likely to be wrong, and untested. Three facts make
them sound and none is local: one query index yields exactly one response (so a `BTreeMap` keyed by
index cannot overwrite), `End`'s index is always one past the last response index (so it can share
that map), and a stashed response keeps its original arrival stamps. The first of those is what
[item 52](known-issues.md#52-a-resident-hit-in-exists-answers-a-query-a-blocked-clone-will-answer-again)
violates.

**[Wire Protocol](../architecture/wire-protocol.md#what-the-framing-does-when-it-goes-wrong)** —
what the framing does when it goes wrong. The two directions are asymmetric in a way nothing said:
the client returns an error, the server panics its shard and with it every other client that shard
was serving. Plus the two properties of the format itself — no maximum message size, and no
deadline on a frame, so a peer that sends a length prefix and then stops parks the reader forever.

**[Compaction](../storage/compaction.md#none-of-the-above-has-ever-run-in-a-test)** — the untested
surface, named line by line. Compaction is the only component that rewrites committed data and none
of it executes in the suite, because `MIN_ARCHIVE_COMPACTABLE` is 10 MiB and no test writes near
that. The 50% utilisation decision, the rewrite, active-archive rotation, archive deletion and
`sort_by_load` have never run. [Archives and the Archive Map](../storage/archives-and-map.md) gained
the other half of that: the `loaded_archives` descriptor cache is unbounded, and the loader's retry
classification exists to ride out exactly the `EMFILE` it makes more likely.

## What the next review should do differently

- **Check the links first.** It costs thirty seconds with a script and found four real breaks that
  the book's own build cannot see. It should be a test, not a review step
  ([TODOs](todos.md#documentation)).
- **Re-measure item 38's port table rather than reading it.** It has been wrong about the *number
  of binaries* since F9, not merely about the endpoints, and it will be wrong again the next time
  someone adds a test binary that starts a server.
- **Count the in-code `TODO`s.** The header said seven over a list of eight, which is the cheapest
  possible drift and survived several passes.
- **Do not trust a citation inside a quoted historical entry.** Three separate places on
  [Optimizations](optimizations.md) quote an entry's original text, and every line number in those
  quotes is now wrong by construction. They are annotated; a future one will not be unless someone
  remembers.
- **The counts were right.** Four sweeps in a row have re-derived the test totals and found them
  accurate. That is evidence the "up from" chain is being maintained honestly, and a reason to
  spend the next review's time on the source instead.
